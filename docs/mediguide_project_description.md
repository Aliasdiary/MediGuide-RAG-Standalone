# 基于混合检索与 Retrieval-Aware SFT 的医疗健康问答 Agent

## 项目背景

面向医疗健康科普与风险提示场景，项目设计并实现本地化医疗问答 Agent，支持症状风险识别、疾病知识科普、用药安全提示及检查与治疗知识问答。系统通过外部知识检索、领域微调和安全校验提升回答的可追溯性与可靠性，避免通用大模型在医疗问题中直接裸答导致的事实幻觉、越界诊断和错误用药建议。

## 核心流程

```text
中文问题
-> 风险/意图识别
-> 双语查询扩展
-> BGE-M3 + FAISS 语义检索
-> BM25 关键词检索
-> RRF 融合排序
-> Cross-Encoder Reranker（可选）
-> Parent Document 回填与去重
-> Evidence Gate 证据门控
-> Retrieval-Aware Qwen2.5-3B SFT 生成
-> 生成后安全校验
```

## 关键实现

1. **医疗知识库构建**：基于公开医疗问答数据集 MedQuAD 搭建 ETL 流程，完成 XML 解析、数据清洗、分层抽样、JSONL 转换与版本管理，保留疾病主题、问题类型、来源机构及来源链接等元数据。

2. **父子文档建模**：完整医疗问答作为 Parent Document，问题文本作为 Child Chunk，并维护 Child-to-Parent 映射，实现“小片段检索、完整问答回填”。

3. **跨语言混合检索**：使用 BGE-M3 构建中英文跨语言向量表示，结合 FAISS 向量检索与 BM25 关键词检索多路召回，通过 RRF 融合排名，并支持 Cross-Encoder Reranker、父文档去重和动态 Top-K。

4. **证据门控与主体一致性**：设计 Evidence Gate，对候选文档中的疾病、药物、检查项目、目标人群和问题类型进行一致性检查，将检索结果划分为证据充分、部分充分、证据不足和主体错配等状态，过滤高排名但主体错误的文档。

5. **RAG-SFT 融合**：将 RAG 实际召回的医疗文档加入 Qwen2.5-3B-Instruct 的训练输入，构建 Retrieval-Aware SFT 统一生成模型，使检索结果直接进入经过领域微调的生成模型。

6. **检索感知数据构造**：基于真实 FAISS、BM25 和 RRF 召回结果挖掘 hard negative，构造正确证据、干扰证据、部分证据、无证据及医学主体错配样本，使模型学习证据筛选、噪声过滤和证据不足拒答。

7. **QLoRA 微调与部署**：基于 LLaMA-Factory 和 QLoRA 在 RTX 4090 单卡环境微调 Qwen2.5-3B-Instruct，混合原医疗科普 SFT 数据与 Retrieval-Aware SFT 数据，完成 LoRA 权重合并，并通过本地推理脚本接入 RAG 生成链路。

8. **统一医疗安全链路**：结合生成前风险路由、模型内部安全行为对齐和生成后输出校验，限制疾病诊断、处方建议及个体化剂量输出；对高风险症状触发及时就医提示。

## 评估结果

项目采用“用户端无引用展示、系统端保留证据决策信息”的评估方式。由于最终回答不展示资料编号和 URL，核心指标不再使用引用准确率或引用覆盖率，而是评估回答内容是否真正被输入证据支持。

核心评估指标包括：

- **事实支持率**：回答中的医学事实要点是否被输入证据支持。
- **未支持事实率**：回答中无法由检索证据支持的医学结论比例。
- **错误证据影响率**：模型是否吸收高相似错误文档或主体错配文档的信息。
- **主体一致率**：回答中的疾病、药物、检查项目是否与用户问题一致。
- **无证据拒答正确率**：证据不足或主体错配时，模型是否能避免强行给出医学结论。
- **错误强答率**：没有可靠证据时仍然输出明确医学结论的比例。

已有基线评估中，MediGuide-SFT 相比基础 Qwen2.5-3B-Instruct 的医学关键词覆盖率由 **67.9%** 提升至 **74.6%**，急症风险提示率由 **95.0%** 提升至 **100.0%**，综合可用性由 **77.1%** 提升至 **79.1%**。原 RAG 系统相比直接 LLM 回答的综合可用性由 **75.0%** 提升至 **98.7%**。统一 RAG-SFT 链路后，评估重点调整为事实支持率、错误证据影响率、主体一致率和无证据拒答表现。
